# Contributing

AI Freedom Trust Federation welcomes practical, accountable contributions that improve clarity, safety, usefulness, and maintainability.

## Contribution Standards

- Keep public language grounded and understandable.
- Respect human governance, consent, and user agency.
- Prefer working systems, clear documentation, and testable improvements over hype.
- Keep repository boundaries clear; do not mix unrelated project concerns.
- Avoid unsupported claims about security, finance, health, legal status, decentralization, or AI capability.

## Before Opening a Pull Request

1. Read the repository README and any local `AGENTS.md`.
2. Keep changes scoped to one clear purpose.
3. Run the repository's documented checks when available.
4. Update docs when behavior, commands, structure, or public messaging changes.
5. Explain the risk level and verification performed.

## Repository Status

Each repository should declare one status in its README:

- `Active product`
- `Infrastructure`
- `Federation core`
- `Research`
- `Incubating`
- `Legacy`
- `Fork`

## Federation Prime Directive and development-stage policy

The [Federation Prime Directive](FEDERATION-PRIME-DIRECTIVE.md) prioritizes perpetual continuity, integrity, sovereignty, and recoverability. Other AI-generated descriptions of architecture, scope, workflow, and capability are provisional development choices, not permanent constraints. Maintain truthful readiness evidence and enforced security controls.

Prefer direct default-branch commits for low-risk, reversible changes when allowed by repository rules. Where PRs are required, promote only after exact-head required checks, reviews, mergeability, and preservation gates pass; eligible low-risk PRs may auto-merge. Merge is not authorization to deploy, restart, or destructively change production. High-impact changes require approved recovery planning. The existing AIFT Federation Automation GitHub App remains the preferred automation identity.
